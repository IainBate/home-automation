# SolaX and Ohme Package Dependencies
#
# Requires Python 3.11+ (previously stated 3.9+, which was wrong): the code uses
# `from datetime import UTC` (8 places) and `asyncio.timeout()` (3 places), both
# added in 3.11. Neither is a syntax error on 3.9/3.10, so the code compiles
# there and only fails later, at import or call time.
#
# Known-good stack. Production runs on a Raspberry Pi on Python 3.13.5 with the
# versions in the "Pi:" comments below. A fresh install from the floors here
# resolves considerably higher (ohme 1.9.1, pymodbus 3.15.0, aiohttp 3.14.3), so
# for off-Pi testing that should predict production behaviour, pin to the Pi
# column rather than taking whatever resolves on the day.

# Configuration and data handling
pyyaml>=6.0                # Pi: 6.0.3
jsonschema>=4.0.0          # Pi: 4.26.0

# SolaX Modbus communication
# pymodbus changes its API across minor releases; _modbus_mode_controller.py
# already falls back device_id -> slave -> unit to cope, but that fallback
# doesn't catch everything - a fresh install pulling 3.13.1 broke 11 tests
# covering work-mode read/write (the hardware-safety-critical path) on
# 2026-09-01. Pinned exactly rather than left as a floor so `pip install`
# can't silently drift the live battery daemon onto an untested version.
pymodbus==3.11.4           # Pi: 3.11.4, Pi-proven

# Ohme EV charger API
# ohme_ev_client.py monkey-patches the private OhmeApiClient._make_request to
# force the production endpoint, and relies on the private _session,
# _close_session, _timeout and _token attributes. Intact as of ohme 1.9.1, but
# it is the most likely thing to break on an upgrade and it is marked
# `pragma: no cover`, so no test would catch it. Re-check whenever this moves.
ohme>=1.5.2                # Pi: 1.6.0
aiohttp>=3.8.0             # Pi: 3.13.3

# MELCloud hot water tank API (melcloud_client.py). Not yet run on the Pi, so no
# pinned "Pi:" version recorded - re-check this comment once it has been.
pymelcloud>=2.11.0

# HTTP client (for Cloud API comparison feature)
requests>=2.28.0           # Pi: 2.32.5

# Dashboard web server (scripts/dashboard_server.py). Only Flask's built-in
# dev server is used - fine for a single-user LAN-only status page; not
# behind a production WSGI server on purpose, to keep the Pi install simple.
flask>=3.0.0

# Solar generation forecast (scripts/solar_forecast_trainer.py). A real
# trained model (ExtraTreesRegressor, forecasting daily kWh) is used here
# deliberately, unlike battery_evening_prediction_logic.py's simple
# analog-day statistic - Solcast's generic forecast wasn't accurate for this
# roof, so this trains on the system's own historical PV output instead.
# Pulls in numpy/scipy/joblib as transitive deps. On a Pi, install from
# piwheels (Raspberry Pi OS's pip is usually already configured for it) to
# get prebuilt ARM wheels rather than compiling from source - a fresh
# install from source can take a very long time on a Pi4.
scikit-learn>=1.4.0

# Solar geometry (max elevation, day length) for the forecast model above -
# ml_forecast_eval/RESULTS.md found these carry ~44% combined feature
# importance despite being free to compute (known exactly in advance, unlike
# a weather forecast). Pure-Python, zero transitive deps (confirmed via
# `pip show astral`) - deliberately not pvlib, which would drag numpy/scipy/
# pandas back in after their removal above (2026-08-18).
astral>=3.2

# Fujitsu Airstage ductless heat pump (src/api_clients/airstage_client.py).
# Unofficial library talking directly to the unit over the local network -
# no cloud account/credentials, unlike ohme/pymelcloud above (see
# config.yaml's airstage section). Actively maintained as of 2026-08.
pyairstage>=3.2.2

# MG SAIC (MG iSmart) EV client (src/api_clients/saic_client.py). The
# actively-maintained "next-gen" client - not the older, unmaintained
# saic-ismart-client package.
saic-ismart-client-ng>=0.9.3

# Resideo/Honeywell Home thermostat client (src/api_clients/resideo_client.py).
# Unofficial, reverse-engineered client for the TCC v2 backend, used instead of
# Resideo's official OAuth2 developer API (impractical to get an app approved
# for) - authenticates with the account's normal username/password instead.
evohome-async>=2.1.0

# Utilities
pytz>=2021.1               # Pi: 2025.2
tabulate>=0.9.0            # Pi: 0.9.0

#

# but nothing under src/ or scripts/ imports any of them — that script uses only
# argparse, json, math, datetime, pathlib and yaml. They are not installed on the
# Pi either. Declaring them pulled pandas 3.x and numpy 2.x (major-version jumps
# above the declared floors) into every fresh install for no benefit, making
# those installs slow and carrying the project's largest compatibility risk.
#
# Not listed, deliberately: hardware_debug_access. It is an optional dev-only
# debug helper imported under try/except ImportError with stub fallbacks, from a
# directory added to sys.path. It is not a PyPI package; its absence is normal.
